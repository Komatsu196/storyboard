# プロダクト概要 — 絵コンテ管理アプリの方向性

最終更新: 2026-09-14
出典: [決定事項ログ](./decisions.md) D-001〜D-015。詳細な背景・含意はそちらを参照。

## 一行で

**ラフな絵コンテをその場で描いて、撮影情報を書き込み、撮影当日にスマホで見返せる — 実写映像の個人制作向け、1ツールで完結する手軽な絵コンテアプリ。**

## 誰のため（D-001, D-002）

- 開発者本人。実写のショートフィルム・MV を個人で制作している。
- チーム利用・共有・汎用化は当面考えない。「自分のワークフローに刺さるか」だけで判断する。

## 解く課題（D-004, D-011）

- **今**: 紙・iPad で描いた絵と、カメラ・尺・セリフなどの撮影情報がバラバラで、一緒に持てない。
- **これから**: 「1カット＝画＋撮影情報」をひとつの単位として、**描く → 書く → 見返す** を1ツールで完結させる。
- 描画の品質は求めない。**ラフで良いからこそ速く、1ツールで完結できる**ことが売り。

## 設計原則（D-006）

> できる限りシンプルに。迷ったら足さない。自分が毎回使うものだけを入れる。

## 使う場面と端末（D-008, D-010, D-012）

| 場面                     | 端末             | 主な操作                                   |
| ------------------------ | ---------------- | ------------------------------------------ |
| 構成を組む・描く         | PC（ペンタブ）   | サムネイルのグリッド一覧、スケッチ、情報入力 |
| 空き時間に描く・書き足す | スマホ（指）     | 「＋カット」→ 即スケッチ、情報入力         |
| 現場で見返す             | スマホ           | 1カットずつ縦スクロール閲覧                |

- 常時オンライン前提（オフライン対応なし）。
- iPad（Apple Pencil）・マウス向けの作り込みはしない。

## データ構造（D-007, D-013）

```
作品      : タイトル / アスペクト比（16:9 | 9:16 | 4:3 | 2.39:1、既定 16:9）
 └ シーン : シーン番号 / タイトル
    └ カット: カット番号（必須）/ 画（スケッチ）/ ショットサイズ / カメラの動き /
             内容（芝居・アクション）/ セリフ・音 / 尺（秒）/ 備考
```

- 必須はカット番号のみ。他はすべて空で保存できる。
- ショットサイズ・カメラの動きは固定の選択肢（LS/FS/MS/BS/CU/ECU、Fix/Pan/Tilt/Dolly/Handheld/Gimbal＋自由入力）。

## MVP スコープ（D-013）

**Must（優先順）**

1. **スケッチキャンバス（中核）** — ペン（太さ2〜3段階）・消しゴム・取り消し/やり直し・全消し。色は黒＋赤。作品のアスペクト比のフレーム枠を表示。あとから開いて追記・消去できる。指・ペンタブで描け、描画中にページがスクロールしない。
2. **カット追加 → 即キャンバス**の動線（特にスマホ）
3. カット情報8項目の入力・編集（キャンバスと同じ画面で）
4. 作品・シーン・カットの作成・並べ替え・削除（自動採番・番号の手動調整）
5. PC 向け一覧: スケッチのサムネイルを並べたグリッド
6. スマホ向け閲覧: 1カットずつ縦スクロール
7. 自分だけが使えるログイン

**Later（MVP の次）**
画像アップロード（紙・iPad の絵の取り込み）、画像の一括取り込み、カットの複製・シーン間移動、尺の合計表示、検索・タグ、色の追加、スケッチへのテキスト入力

**やらない（決定済み）**
本格描画（レイヤー・ブラシ）、PDF/印刷、共有・複数ユーザー、オフライン、iPad/マウス向けの作り込み

## 成功基準と期限（D-013, D-015）

- **期限**: 2026-10-14 までに使い始められる状態にする。
- **成功基準**: 自分の1本（ショートフィルム or MV）を、紙・iPad・他ツールを併用せずこのアプリだけで描き切り、撮影を終えられる。
- 進め方: まずスケッチキャンバス（Must 1〜3）を最初の1〜2週間で触れる状態にし、残りで一覧・並べ替え・ログインを足す。

## 技術上の制約（D-014）

- フロントは **Vite + React + TanStack Router の SPA**。TanStack Start は使わない。
- DB・ストレージは提案制（Cloudflare D1 などが候補）。ホスティングは Cloudflare 前提。個人利用なので無料枠に収まる構成にする。
- SPA から D1/R2 に触るための軽量 API（Cloudflare Workers）が必要。
- 現在の `apps/web` スキャフォールド（TanStack Start + Drizzle/MySQL）は組み直す。Tailwind / Biome / Drizzle は流用候補。
